# dsh-stream-motion

**回答流式输出时，聊天区做两件事：新到的字逐字淡入，被宿主贴底推上去的文字被滑回原位，而不是跳一下；工具与思考行的开合也卷动高度，而不是整块瞬移。**

[![English](https://img.shields.io/badge/lang-English-blue.svg)](README.en.md)

</div>

一个 DeepSeek Harness 插件。淡入与滑移来自
[dsh-claude-style](https://github.com/nwflower/dsh-claude-style)，在那里它们是某个主题的两个功能；
这里是一个不需要主题的独立插件。具体哪些是移植、哪些是新写的，见[参考项目](#参考项目)。

## 支持的 DSH 版本

**只支持 DSH `0.2.3-alpha.2`。** manifest 精确锁定该版本 ——
`"engines": { "dsh": "0.2.3-alpha.2" }` —— 其他版本安装会被直接拒绝
（`incompatible-version`），而不是先装上再出问题。

精确锁定是故意的。这个包抓着聊天框的 DOM 形状：找「回到底部」按钮靠从列元素的祖父走到
下一个兄弟槽位；读的是宿主自己节点上的 `data-chat-following-tail` / `data-chat-flow` /
`data-chat-running` / `data-step-process-body`；写的是宿主拥有的滚动容器。这些都是宿主内部
实现，不是公开契约。用 caret 范围会放行 `0.2.3-alpha.3`、`0.2.3-beta.1`、`0.2.3` 和
`0.2.4` —— 它们都是看着合理的预发布或补丁步进，但一个都没在这里验证过。在没跑过的版本上，
失败是静默的，比拒绝更糟：框架挪了位置就答「没有按钮」，跟随交还悄悄失效；标记改名让守卫
永远读到 `false`；滚动容器换了主人，位置仲裁就变成第二个写入者跟宿主打架。

放宽版本是一条**测试**动作，不是改个版本号。对新运行时跑
`node test/reveal-probe.mjs`、`node test/follow-probe.mjs`、`node test/tail-press.mjs`
和 `node test/live.mjs`，并把「工作原理」一节的标记表对着宿主的 `dsh-client-ui-chat`
构建重新核一遍，再去动范围。

非要在未验证版本上装，DSH 提供针对具体运行时的精确版本豁免 ——
`dsh-stream-motion@0.2.1`，通过插件管理器或 `dsh plugin allow-version`。之后发生什么按未测处理。

## 安装

```bash
npm install          # 只为了 esbuild 这一个开发依赖
npm run build        # src/ -> lib/client.js + lib/host.js
```

然后把 DSH 的插件管理器指向本目录（`install_bundle`），或把构建好的目录作为本地 bundle 安装。
`lib/` 已入库，所以 clone 下来可以直接装；改过 `src/` 再重新构建。

## 它做什么

**淡入。** 字先以低不透明度出现，再落到实色，每帧一个 alpha 台阶，于是长回答读起来像在写，
而不是一块一块地蹦出来。到达顺序被保留：后到的一批不会超过先到的；淡入的时长跟着相邻两批
之间的间隔走。

**滑移。** 回答流式输出时，宿主把对话钉在末尾：每到一个片段就整段写一次末尾，于是最后一
行以上的文字在一帧之内被推上去「增长量」那么多。这个插件把列元素按同样的增长量放回来，并
在合成器上滑到静止，读者的眼睛留在同一行上，而不是每次爆发都被踢一下。当前轮次那一行被钉
在滚动容器底部，会跟着这个位移走，所以它在同一帧里反向滑移同样的量，原地不动。

**跟随交还。** 聊天区的跟随会在几个时刻丢失 —— 折叠滑移落地、切换会话、恢复历史，以及读者
自己滚走之后又回来。宿主在自己的 500 ms 采样窗口里遇到任何写入都会关掉跟随，只留一条回头
路：那个只在关闭状态下才渲染的「回到底部」按钮。守卫替你按它。

流式输出期间的结构时刻（工具行挂载、思考行离开 `running`、新内容块挂上）**不需要**交还：
宿主自己会在这些时刻保住跟随。上游在真实宿主上测过 —— 关掉皮肤的跟随跑一个流式回合，宿主
一帧都没丢；开着皮肤时这条交还按下按钮 0 次。所以这里只留折叠与读者自己的两处交还。

宿主把那个按钮放在列的右侧空隙里、对话区水平居中。这个包把它挪到输入框右上角的外侧 ——
读者真正在看的地方，因为文字末尾就在输入框正上方 —— 并以右边缘对齐，这样按钮自己的宽度
不需要被知道。两个数每次都重新测，因为两条边都会动：草稿换行时输入框会长高，侧边栏会从列
里拿走宽度。

**锚点是整个输入区的顶边，不是卡片自己的。** 宿主会把整宽的条目堆在输入卡片上方、同一个
列里 —— 任务时间线、排队、目标，全都注册在 `conversation.input.dock` 这个插槽上，而该插槽的
契约原文就是「full-width entries above the composer card」。它们是卡片的兄弟节点，各自套在
一层 `display: contents` 包装里，那层包装没有自己的盒子，所以卡片的 `top` 对它们一无所知。
真机上量到的是：卡片从 770 起，时间线占 728–764；只按卡片顶端算，按钮落在 726–758 —— 几乎
整条压在进度条上。修法是从卡片往上走祖先，把 `height > 0` 的盒子顶端一路收拢到「装得下对话
滚动容器的那一层」为止（再往上就是聊天区，不是输入区了），用收拢到的最高点当锚。

**上移是滑过去的。** 停靠条挂上或摘下会把锚点整条挪开（时间线自己 36px 加上间隙），瞬间
跳过去再跳回来读起来就是故障。所以 `bottom` 与 `right` 各带一条 180 ms 的过渡
（`TAIL_MOVE_MS`/`TAIL_MOVE_EASE`，`cubic-bezier(0.32, 0.72, 0, 1)`：立刻起步、不过冲）；
页面声明 `prefers-reduced-motion: reduce` 时过渡整条去掉，直接落到新位置。

**平滑按下。** 按那个按钮本身也被平滑了。宿主的处理函数一帧写到底，等于把读者瞬移过去；
这个包在宿主处理函数之前截下这次点击，用一条定时缓动把位置走到末尾 —— 起步慢、中段最快、
贴着目标收住 —— 然后再真的按一次按钮，把宿主的跟随打开。用定时缓动而不是弹簧，因为这段
行程的形状是给读者看的；弹簧渐近逼近目标，最后几像素会爬，而且它的前置量会在第一帧就把
读者挪走一屏。时长从距离读出（`sqrt(px) * 12`，夹在 220–700 ms），短程快、长途不熬。

**追赶。** 被限高的过程体（可折叠的工具输出）落后超过 40 px 后，会用一条临界阻尼弹簧走到
自己的末尾，读起来是追赶，而不是宿主那种慢悠悠的平滑滚动。

**折叠。** 宿主的思考行与工具行靠一次提交就插入或摘掉正文，中间没有任何过渡，于是它们下面
的所有内容一帧之内挪掉「正文高度」那么多。这个包在中间放一段高度动画：关闭时在正文还挂着
的时候截下点击，把正文卷上去，落地之后再真的按一次按钮；打开时放行，等宿主插好正文，从它
关闭时的高度卷出来。超过一屏的盒子先走屏幕上可见的那一段，否则可见文字会被带着飞过去。

## 工作原理

这里没有任何东西解析网络流。所有输入都是宿主已经写好的标记，本包不在聊天树里写任何标记：

| 标记 | 宿主写在哪 | 这里当作 |
| --- | --- | --- |
| `data-streaming`、`data-shimmer` | 回答容器 / 思考摘要 | 内容正在到达 |
| `data-chat-following-tail` | 聊天根节点 | 宿主自己的跟随是开着的 |
| `data-chat-flow` | 流列元素 | 被滑移的那个盒子 |
| `data-conversation-scroll` | 对话滚动容器 | 位置的所有者 |
| `data-chat-running` | 当前轮次的行 | 钉在容器底部，需要反向滑移 |
| `data-step-process-body` | 被限高的工具组主体 | 要追赶的盒子 |
| `data-disclosure-row`、`aria-expanded`、`aria-controls` | 折叠控制与它开的主体 | 一扇门 |
| `data-conversation-session`、`data-phase` | 对话体与根节点 | 屏幕上哪个会话 |

淡入骑在 `::highlight()` 上：这个伪元素的属性集里没有 `opacity`，所以 alpha 花在颜色上，
每个台阶一条规则，各自把元素自己发布的颜色与 `transparent` 混合。规则的主语是文字所挂的
那个元素 —— 绝不是「流式块下面的任何东西」，因为后代组合器主语会让每一批都重新匹配它下面
的每一个元素，实测就是流式期间整页 style recalc。

颜色**在绘制帧里读，不在变更回调里读**。标记与读色因此是两件事：给元素写一个属性是写，
写本身不会让浏览器解析样式；`getComputedStyle` 会 —— 它答一个活对象，从上面取第一个属性
就为整篇文档解析样式。在一个变更回调里做这件事，正是新文本刚把树弄脏的时刻，那一次读当场
付掉整篇重算的钱。真实流式上实测：一个回调在一轮回复里累计 2281 ms，而它自己的工作只有
5 ms。所以扫描只打标记，颜色留到绘制帧 —— 那一帧浏览器本来就要解析样式才能画。

固定批数的对照（`test/append-cost.mjs`，240 批，同一页同一容器）把这件事量清楚了：
在回调里读约 50–75 ms 一次，把同一个回调推到 rAF 里读约 0.05–1 ms 一次，快约一千倍；而
`getComputedStyle` 调用本身两侧都只有 2–4 ms，所以贵的是**在样式已脏时**读它，不是调用。
推到帧里也没有把成本转进帧：`per-frame` 与「整个回调丢掉」两臂的帧间隔几乎相同
（`p50 73.4` vs `70`，`over50 239` vs `240`）。

绘制帧还记住上一帧每个台阶画的是哪些段。一个 run 在一个台阶上停
`CHAT_REVEAL_MS / CHAT_REVEAL_STEPS`（30 ms），比一帧长，所以大约每隔一帧某个台阶的段
与浏览器正在画的是同一批；再交一遍会让它重建那个台阶的高亮标记，而重新给出一份没变的
高亮是这一帧里贵的那一半。段相同就跳过，只花一次比较。

滑移是流列元素上的一个 `Animation`：`translateY(距离)` 到 `translateY(0)`，曲线
`cubic-bezier(0.22, 0.61, 0.36, 1)`，时长取相邻两批之间的间隔（上限 240 ms）；一次提交塞进
一屏以上时改由距离定时（`sqrt(px) * 12`，上限 620 ms），否则固定时长会把整屏在几帧里扫过去。
**同一时刻只跑一段替换式动画**：新的增长到来时，把上一段尚未走完的剩余距离与新增长相加，从
这个和重开一段。位移因此从上一帧站着的地方继续，只会向上、不会回弹；而替换式变换留在合成器
上，每帧不必回主线程重绘（加法合成恰好相反：求和不会回弹，但上不了合成器）。

滑移被提前结束时**缓动收尾，不硬取消**。`cancel()` 会让列在一帧之内落回 `translateY(0)`，
而那个位移正是内容被画在最终位置下方的距离 —— 一次取消就是一次单帧上跳。真实回复上实测：
宿主随着回答变长反复重挂流式容器，每次重挂读作一次收缩，于是每轮回复有 25 次取消；用
`cancel()` 时是 574 次超过 2px 的视觉上移、最大 45px，改成 `SLIDE_SETTLE_MS = 320` 的缓动
收尾后降到 217 次、最大 17px。收尾期间记录仍留在 `slide` 里，所以半路到来的增长是加在剩余
距离上，而不是从过期基线重新开始；反向滑移的元素跟着同一段距离反号走。

位移的起点不是尺寸回调，而是**滚动位置本身**：宿主在自己的调度器里写末尾，那次写入可能落在
两次尺寸报告之间，若等到下一次报告才补，增长已经画出来了，补的动作就成了下推。所以位置在
滚动事件里读（渲染步骤中、绘制之前），读到的增量就是这一帧要还的距离。

滚动位置只有一个写入者。六个来源的优先级是
`jump > fold > reader > composer > follow > process`；比正在跑的缓动更低的请求会被拒绝，
读者按住容器时所有跟随类来源都被拒绝。读者一旦滚动就取得按住权，直到他们自己回到末尾。

折叠的卷动也走同一条所有权：卷动期间 `foldBusy()` 为真，跟随的滑移与交还都让位，落地之后再
交还一次，条件是读者起点在末尾且期间没有自己滚动。

## 测试

```bash
npm test                            # 九个浏览器工装
node test/live.mjs                  # 对着正在运行的 DSH web app
node test/fold-live.mjs             # 真实对话里的真实折叠
```

九个工装通过 CDP 驱动无头 Chromium 跑一个假宿主页面，不需要装 DSH。其中六个是回归用的：
`jitter-probe` 逐帧采样一个固定参照块，任何回升都算可见抖动；`race-probe` 让假宿主晚一帧
才写末尾，专门抓「宿主写入与尺寸批次不同步」这一类竞态；`burst-probe` 一次提交塞进一屏以上
的文字；`collapse-probe`、`open-probe`、`group-probe` 覆盖两种门形状的两个方向。

两个 live 套件从运行中应用的日志里读 `?token=` 的 URL，驱动真实的聊天框。`live.mjs` 抓「宿主
挪了位置」这一类形状变化；`fold-live.mjs` 打开一个真实会话，点真实的门，确认卷动真的发生在
真实标记上 —— 它也是唯一能发现「工装假设的形状与宿主不一致」的套件。

`append-cost.mjs` 是这一层里唯一的定量工装：它在真实页面上按固定批数与固定节奏追加元素，
把「在变更回调里读样式」「推到绘制帧里读」「整个回调丢掉」三臂跑在同一页同一容器上，
同时记回调耗时与帧间隔。真实流式的长度不可控（同一配置两轮 `peakRuns` 能差三倍），拿它做
对照读不出差别 —— 这个工装就是为了替掉那种做法。

每次改动的现象、证据、判据与踩过的坑记在 [devlog.md](devlog.md)。那里写的是「这个常量为什么
是那个数」「这段代码在防什么」，改动前值得先看一遍，尤其是「踩到的坑」—— 包括几次「看起来在
测量、其实什么都没测到」的事故。

## 限制

- 只在 DSH `0.2.3-alpha.2` 上测过，manifest 精确锁定该版本。见上面「支持的 DSH 版本」。
- 淡入需要 Custom Highlight API（Chromium 105+、Safari 17.2+）。没有它时淡入退场，滑移照常。
- 滑移需要 `Element.prototype.animate`。没有它时滑移退场，淡入照常。只有两个 API 都缺的
  浏览器什么都拿不到，此时页面不被标记。
- 宿主的「回到底部」按钮靠聊天框的形状找到：列元素的祖父框架，再下一个兄弟槽位。宿主改了
  这个框架就答「没有按钮」，交还与平滑按下都跳过，而不是猜一个。
- 打开在已保存阅读位置的对话永远不算「跟随末尾」，所以交还不会动它：读者自己的位置不会被
  走到末尾。
- 减动效时淡入与滑移都退场，按下交回宿主自己的跳转。减动效从页面读：
  `data-dsh-stream-motion-motion="reduced"` 或 `"full"` 优先，两者都没有时由系统偏好回答。
- 折叠的卷动靠 `data-disclosure-row` / `aria-expanded` / `aria-controls` 找门。宿主换成别的
  折叠标记时，那些门不动画，退回宿主自己的瞬时开关，而不是猜一个。
- 工具组只在被限高时才有可卷的高度。`data-group-expanded-mode` 存在的那一组完全展开、正文
  从不收起，点它只改组自己的开关，插件不介入 —— 给一个不变的高度做动画就是凭空造运动。
- 淡入时长、滑移曲线、追赶阈值与门的卷动时长在这里是常量，不是设置项。

## 参考项目

淡入与滑移是移植，不是发明。两者都来自
**[dsh-claude-style](https://github.com/nwflower/dsh-claude-style)**（作者
[Nwflower](https://github.com/nwflower)，MIT 协议，Copyright (c) 2026 Nwflower），
在那里它们是 Claude Code 风格主题的 `chat-reveal` 与 `chat-follow` 两个功能，跑在一套共享
引擎上（`frame`、`bus`、`scroll-owner`、`scroll-ease`、`chat-dom`）。

从这里移植、为本包重写：

| 本包 | 上游 |
| --- | --- |
| `src/reveal/{diff,engine,paint,text,params}.js` | `packages/client/src/features/chat-reveal/` |
| `src/follow/{follow,scroll-owner,scroll-ease,process-follow,chat-dom,ease}.js` | `packages/client/src/features/chat-follow/` 与 `packages/engine/src/` |
| `src/follow/fold-glide.js` | `packages/client/src/features/chat-fold/{fold-glide,fold-glide-parts}.ts` |
| `src/frame.js`、`src/bus.js` | `packages/engine/src/{frame,bus}.ts` |

移植时改了什么：TypeScript 转 JavaScript；去掉主题的功能注册表、设置行、样式表流水线和皮肤
词汇重写，所以本包不需要主题；所有标记从 `dsh-claude-*` 改名为 `dsh-stream-motion*`；两个
body 门拆开，于是只有其中一个 API 的浏览器仍能拿到它能跑的那一半；`::highlight()` 规则的
主语从一个后代选择器扩成两个，这样「文字直挂在流式容器自身」的情形也能淡入；滑移从滚动事件
起算（上游只在尺寸批次里读）；门的正文在没有 `aria-controls` 时从 root 自己的子元素里找；
